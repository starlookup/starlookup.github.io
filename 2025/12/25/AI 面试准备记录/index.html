第二题

考点：transpose 转置方法。torch 的话，.t() 是一个非常方便的简写方法，专门用于二维张量（矩阵）的转置。

NumPy 的 transpose 实际上更接近于“排列”（Permute）。你可以传递一个轴的列表，一次性改变所有维度的顺序。

  • 语法：arr.transpose(axes)
  • 行为：如果不传参数，默认翻转所有维度（如 $(0, 1, 2) \rightarrow (2, 1, 0)$）。如果传参数，按参数给定的顺序重新排列。

PyTorch 的 transpose 非常“专一”，它一次只能交换 两个 指定的维度。

  • 语法：tensor.transpose(dim0, dim1)
  • 行为：必须指定两个维度，它会把这两个维度的位置对调。

torch.tensor()：安全第一

当你调用 torch.tensor(a) 时，PyTorch 会在内存中开辟一块新空间，把 a 的内容全搬过去。这样原数据 a 和新 Tensor 就彻底“脱钩”了，你修改其中一个，另一个不会变。

torch.as_tensor()：性能第一

它更像是一个“转换器”。它会先检查：“这个东西已经是一个内存连续的数组了吗？它的类型和设备对吗？”

  • 如果输入是 NumPy 数组，它会直接让 Tensor 指向该数组的内存地址。
  • 如果输入已经是 Tensor，且类型（dtype）一致，它不会做任何操作，直接返回原对象。

Transformer模型结构

transformer的左半部分是encoder（编码器），右半部分是decoder（解码器）

1.encoder是由6个相同的层堆叠构成的，即上图中N=6
每一层都有两个子层：
第一个子层是多头自注意力机制（multi-head self-attention mechanism）
第二个子层是全连接的前馈网络（feed forward network）
两个子层之间通过残差连接（residual connection），然后进行层归一化（layer normalization）

2.decoder也是由6个相同的层堆叠构成，即上图中N=6。
每一层都有三个子层：
第一层是带掩码的多头自注意力机制（Masked multi-head self-attention mechanism）
第二层是全连接的前馈网络（feed forward network）
第三层是多头注意力机制，类似于在encoder的第一子层中实现的机制。
在decoder，这种多头注意力机制接收来自前一个decoder层的查询，以及来自encoder输出的键和值。这允许decoder处理输入序列中的所有单词

为什么要位置编码

为什么transformer块使用LayerNorm而不是BatchNorm？LayerNorm 在Transformer的位置是哪里？

  • Encoder：处理完整源序列，把每个 token 的上下文信息编码成隐藏向量（完整可用）
  • Decoder：
    • Masked Self-Attention：屏蔽目标序列中还没生成的部分，只看到已生成 token
    • Cross-Attention：自由访问 Encoder 输出的完整源序列，参考上下文生成下一步 token

所以 mask 只作用在 Decoder 自身的输出上，而 Encoder 的输出是完整可用的。

经典 Encoder-Decoder vs Decoder-Only

特性 Encoder-Decoder Decoder-Only
模块 Encoder + Decoder 只有 Decoder 堆叠
输入 源序列 + 目标序列（训练时用部分目标序列） 只有一个序列（通常是上下文 + 已生成 token）
Cross-Attention 有，Decoder 可访问 Encoder 输出 没有，因为没有 Encoder
用途 机器翻译、条件生成 自回归生成（语言模型）、文本补全
Mask Decoder 自注意力中屏蔽未来 自注意力中屏蔽未来
优势 可以明确利用源序列信息 训练/推理更简单，推理速度快，模型容量集中在一个模块
✅ 总结
  1. 自回归生成天然适合 Decoder-only
  2. 架构简单 → 更易扩展、训练和推理
  3. 可以自由访问长上下文
  4. 统一训练目标 → 大规模数据可用
  5. Prompt 技术 + 巨型模型 → 条件生成无需 Encoder

换句话说：Decoder-only 是大语言模型天然契合的架构，既高效又通用。

GPT 1 Improving Language Understanding by Generative Pre-Trainin

万物起源

摘要 > 自然语言理解包括广泛的不同任务，例如文本蕴涵、问答、语义相似性评估和文档分类。尽管大型未标记文本语料库丰富，但用于学习这些特定任务的标记数据很少，这使得判别训练的模型能够充分执行具有挑战性。我们证明了这些任务的巨大收益可以通过在不同未标记文本语料库上生成语言模型的预训练来实现，然后对每个特定任务进行判别微调。与以前的方法相比，我们在微调期间利用任务感知的输入转换来实现有效的传输，同时需要对模型架构进行最小的更改。我们展示了我们的方法在自然语言理解的广泛基准上的有效性。我们的通用与任务无关的模型优于使用专门为每个任务精心设计的架构的判别训练模型，在所研究的 12 个任务中的 9 个中显着提高了现有技术水平。例如，我们在常识推理（Stories Cloze Test）、问答（RACE）上实现了 8.9% 的绝对改进，在文本蕴涵（MultiNLI）上实现了 1.5% 的绝对改进。

动机 > 团队认为，unlabeled 数据太少了，每个任务都要打标签太累了。于是它们想提出一个泛化性强的预训练模型。

任务覆盖 > 自然语言推理、问答、语义相似性和文本分类

方案 > 提出了 Unsupervised pre-training + Supervised fine-tuning 这种预训练和微调的组合模式，为后面奠定基础。

模型结构与预训练设置 > 模型采用与原始 Transformer 基本一致的 decoder-only 架构（GPT 风格），共 12 层，隐藏维度 768，12 个注意力头，前馈网络中间层维度 3072，使用 masked self-attention 和 GELU 激活函数，并采用可学习的位置编码。模型在 BooksCorpus 上进行无监督预训练，输入为长度 512 tokens 的连续文本序列，batch size 为 64，共训练 100 epochs。文本使用 BPE 分词（40k merges），并通过 ftfy 清洗与 spaCy 分词处理。优化采用 Adam，最大学习率 2.5e-4，前 2000 steps 线性 warmup，随后使用 cosine 学习率衰减。模型使用 LayerNorm，权重初始化为 𝑁 ( 0 , 0.02 ) N(0,0.02)，并在残差、嵌入和注意力层中使用 0.1 的 dropout，同时对非 bias / gain 参数施加权重系数为 0.01 的 L2 正则。

微调设置 > 在下游有监督任务中，模型整体参数继续微调，仅额外引入一个线性分类头，并在分类器上使用 0.1 dropout。除非特别说明，微调阶段沿用预训练的超参数设置；通常使用 6.25e-5 的学习率、batch size 32，并采用 线性学习率衰减（warmup 占训练步数的 0.2%）。模型在大多数任务上收敛较快，3 个 epoch 即可取得稳定性能。此外，微调时联合优化监督损失与语言建模辅助损失，其中辅助 LM 目标的权重 λ 设为 0.5，以提升泛化能力并加速收敛。

结论 > Transformer 的语言模型预训练对下游任务迁移至关重要。随着从预训练模型中迁移的层数增加，下游性能持续提升，表明预训练模型的每一层都学习到了对目标任务有用的通用表示。同时，模型在无监督预训练阶段已显现出稳定增强的 zero-shot 能力，说明语言建模过程本身促使模型习得了多种任务相关的结构化能力。消融实验进一步验证了三点：缺乏预训练会导致所有任务性能显著下降，Transformer 架构在迁移性与稳定性上明显优于 LSTM，以及在数据规模较大的任务中，引入辅助语言建模目标有助于提升泛化能力和优化效率。总体而言，预训练语言模型、Transformer 架构以及辅助 LM 目标共同构成了有效迁移学习的关键因素。

GPT2 Language Models are Unsupervised Multitask Learners

还是迁移性的 zero-shot 的提升，在 GPT-1 基础上更进一步证明 无需微调也可泛化

摘要> 自然语言处理任务，例如问答、机器翻译、阅读理解和摘要，通常通过对特定任务数据集的监督学习来处理。我们表明，当在称为 WebText 的数百万网页的新数据集上进行训练时，语言模型开始在没有任何显式监督的情况下学习这些任务。当以文档加问题为条件时，语言模型生成的答案在 CoQA 数据集上达到 55 F1 - 匹配或超过 4 个基线系统中 3 个的性能，而不使用 127,000+ 个训练示例。语言模型的容量对于零样本任务迁移的成功至关重要，并且它以跨任务的对数线性方式提高了性能。我们最大的模型 GPT-2 是一个 1.5B 参数 Transformer，它在零样本设置中 8 个测试语言建模数据集中的 7 个上实现了最先进的结果，但仍然不适合 WebText。模型中的样本反映了这些改进并包含连贯的文本段落。这些发现表明，构建语言处理系统是一个很有前途的途径，它学习从自然发生的演示中执行任务。

语言建模的本质，是学习“下一个符号在给定历史条件下出现的概率”，而 Transformer 等模型正是用来高效地建模这种条件概率的。

动机> 原则上，语言模型甚至可以在不显式标注哪些符号是需要预测的输出的情况下，学习 McCann et al. (2018) 中的这些任务。这是因为：监督目标本质上与无监督目标是相同的，只不过监督目标只在序列的一个子集上进行评估。因此，无监督目标的全局最优解同时也是监督目标的全局最优解。在这种略显“玩具化”的设定下，Sutskever et al. (2015) 所讨论的、关于密度估计作为训练目标的原则性担忧被回避了。

此时，问题不再是目标函数是否合理，而是：我们在实践中是否能够将无监督目标优化到收敛。初步实验表明，规模足够大的语言模型确实能够在这种近似玩具的设置下实现多任务学习，但其学习速度明显慢于显式监督的方法。

数据集> 这不是“随便选 Reddit”，而是： 用人类行为作为弱监督质量信号 karma ≥ 3 ≈ 人类读过 愿意分享 认为有价值

WebText 的目标不是：

而是：

输入表征> BPE（Byte Pair Encoding）是一种介于字符级与词级之间的子词建模方法，通过基于频率的贪心合并策略，将高频符号序列合并为更长的 token，从而在保留词级建模效率的同时避免未登录词问题；它对常见词倾向于使用整体表示，对罕见或新词则退化为更细粒度的字符或字节表示，因此在词表规模、泛化能力与建模效率之间取得了良好平衡，被广泛用于大规模语言模型中。

尽管 GPT-2 未做监督微调，仍在多数任务刷新 SOTA，但在翻译和事实问答等任务仍远低于专门方法。

测试集与训练集的低重叠表明性能提升主要来自泛化而非简单记忆。

目标：检验 GPT-2 的性能是泛化还是简单记忆训练数据。

方法：通过 8-gram Bloom filter 分析训练集与测试集重叠。

主要发现：

  • 大部分评测数据与 WebText 重叠率低 → 性能主要来自 泛化。
  • 高重叠样本略微提升困惑度或 F1，但整体影响很小。
  • GPT-2 在自身留出集表现同步提升 → 模型仍在欠拟合，未靠记忆训练数据获益。

建议：使用 n-gram 去重和重叠分析作为数据集构建和验证步骤。

结论 > 以往研究主要关注监督和无监督预训练方法的表示学习、理解与评价。

本文结果表明 无监督任务学习（unsupervised task learning） 是一个有前景的研究方向。

在极限情况下，预训练技术能够直接学习执行任务，无需监督微调或架构修改，这可能解释了预训练在下游 NLP 任务中成功的原因。

实际应用中，GPT-2 的零样本表现仍远未达到可用水平。

研究涵盖了多种经典 NLP 任务，但仍有许多任务 GPT-2 的表现接近随机。

对于问答和翻译等任务，模型需足够容量才能超过简单基线。

GPT3 Language Models are Few-Shot Learners

摘要> 最近的工作通过在大型语料库上进行预训练，然后在特定任务上进行微调，在许多 NLP 任务和基准上展示了显着的收益。虽然通常在架构中与任务无关的，但这种方法仍然需要数千个或数万个示例的特定于任务的微调数据集。相比之下，人类通常只能从几个例子或简单的指令执行新的语言任务——当前的 NLP 系统仍然很大程度上难以做到这一点。在这里，我们表明扩展语言模型可以大大提高与任务无关的、少样本的性能，有时甚至达到与之前最先进的微调方法的竞争力。具体来说，我们训练了 GPT-3，这是一种具有 1750 亿个参数的自回归语言模型，比任何以前的非稀疏语言模型 10 倍，并在少样本设置中测试其性能。对于所有任务，GPT-3 在没有任何梯度更新或微调的情况下应用，任务和少样本演示纯粹通过与模型的文本交互来指定。GPT-3 在许多 NLP 数据集上取得了强大的性能，包括翻译、问答和完形填空任务，以及几个需要即时推理或域适应的任务，例如非加扰词，使用句子中的新词，或执行 3 位算术。同时，我们还确定了一些 GPT-3 的小样本学习仍然存在困难的数据集，以及一些 GPT-3 面临与大型 Web 语料库训练相关的方法问题的数据集。最后，我们发现 GPT-3 可以生成人类评估者难以与人类撰写的文章区分开来的新闻文章样本。我们通常讨论这一发现和 GPT-3 的更广泛的社会影响。

“规模驱动的隐式元学习”的开山之作

与此同时，语言建模领域的另一个趋势或许能够带来突破。近年来，Transformer 语言模型的规模显著增长：从 1 亿参数 [RNSS18]，到 3 亿 [DCLT18]，再到 15 亿 [RWC+19]，随后是 80 亿 [SPP+19]、110 亿 [RSR+19]，直至 170 亿参数 [Tur20]。每一次规模提升都带来了文本生成质量和/或下游任务性能的改善，并且有证据表明，与许多下游任务高度相关的对数损失（log loss）会随着模型规模呈现出平滑的改进趋势 [KMH+20]。由于上下文学习需要将大量技能和任务内化到模型参数中，因此可以合理推测，其能力也会随着模型规模的增大而显著增强。

基于这一假设，本文训练了一个拥有 1750 亿参数 的自回归语言模型，即 GPT-3，并系统评估了其上下文学习能力。具体而言，我们在二十多个 NLP 数据集上评测 GPT-3，同时还设计了一些新的任务，用于测试模型对训练集中不太可能直接包含的任务的快速适应能力。对于每个任务，我们在三种设置下进行评估：(a) 少样本学习（few-shot），即在上下文窗口允许的情况下提供尽可能多的示例（通常为 10 到 100 个）；(b) 单样本学习（one-shot），仅提供一个示例；(c) 零样本学习（zero-shot），不提供示例，仅给出自然语言指令。原则上，GPT-3 也可以在传统的微调设置下进行评估，但本文将其留作未来工作。

模型> 我们使用与GPT-2 [RWC+19]相同的模型和架构，包括其中描述的修改初始化，预归一化和可逆标记化，除了我们在变压器层中使用交替的密集和局部带状稀疏注意模式，类似于稀疏变压器[CGRS19]。为了研究机器学习性能对模型大小的依赖性，我们训练了8种不同大小的模型，从1.25亿个参数到1750亿个参数的三个数量级，最后一个是我们称之为GPT-3的模型。先前的研究[KMH+20]表明，如果有足够的训练数据，验证损失的缩放应该近似为一个平滑的幂律，作为大小的函数；训练许多不同大小的模型使我们能够测试验证损失和下游语言任务的假设。

训练集>

  1. 基于与多种高质量参考语料的相似度，对 Common Crawl 进行下载和过滤；
  2. 在文档级别进行模糊去重（fuzzy deduplication），并在不同数据集之间执行去重，以防止数据冗余，同时确保保留的验证集仍能作为衡量过拟合的可靠指标；
  3. 将已知的高质量参考语料加入训练数据混合中，以增强 Common Crawl 的多样性和整体质量。

前两点（Common Crawl 的处理流程）在附录 A 中有详细描述。对于第三点，我们加入了若干经过精心整理的高质量数据集，包括：

  • 扩展版 WebText 数据集 [RWC+19]，该数据集通过在更长时间跨度内抓取网页链接构建，并首次在 [KMH+20] 中进行了描述；
  • 两个基于互联网的英文图书语料库（Books1 和 Books2）；
  • 英文维基百科（English Wikipedia）。

Common Crawl 数据来自 2016–2019 年期间的 41 个按月切分的数据分片（shards），在过滤前共计 45TB 的压缩纯文本，过滤后约为 570GB，大致相当于 4000 亿个 BPE（字节对编码）token。

需要注意的是，在训练过程中，各数据集的采样比例并非严格按照其原始规模进行。相反，我们会更频繁地采样我们认为质量更高的数据集。因此，Common Crawl 和 Books2 数据集在整个训练过程中并不会被完整遍历一次，而其他数据集则会被采样 2–3 次。这种做法本质上是：接受少量过拟合的风险，以换取更高质量的训练数据。

数据污染问题（Data Contamination）

对于在大规模互联网数据上进行预训练的语言模型而言，尤其是具有强大记忆能力的大模型，一个重要的方法论问题在于：下游任务的测试集或验证集可能在预训练阶段被模型“见过”，从而导致评测结果被污染。为减少这种数据污染，我们尝试搜索并移除本文所使用的所有基准数据集中，与其验证集和测试集存在重叠的样本。

不幸的是，由于过滤流程中的一个 bug，我们未能成功移除所有重叠数据；并且由于训练成本极高，重新训练模型并不可行。我们在第 4 节中对这些残留重叠的影响进行了系统分析，并计划在未来工作中更为严格地消除数据污染问题。

Common Crawl 数据过滤与模型训练总结：>

  1. Common Crawl 数据过滤：
    使用了两种技术来提高 Common Crawl 数据集的质量：
    • 自动过滤： 使用高质量数据集（如 WebText、Wikipedia）训练一个分类器，过滤掉低质量的文档。分类器为文档评分，通过重新采样保留大多数高质量文档，同时保持一些多样性。
    • 模糊去重： 使用 MinHashLSH 实现去除高重叠的文档，以避免过拟合并提高模型质量。此外，还将 WebText 从 Common Crawl 中移除，防止数据污染。这个过程使数据集大小减少了约 10%。
  2. 模型训练：
    GPT-3 的训练使用了 Adam 优化器，并设定了特定的超参数，包括学习率衰减、权重衰减用于正则化以及梯度裁剪。训练过程中采用了高效的令牌打包方式，使用 2048 令牌的上下文窗口，不需要针对特定序列的掩码。
  3. 测试集污染研究：
    • 初步过滤： 尝试通过查找 13-gram 重叠来移除基准数据集中出现的训练数据，重叠部分被删除或拆分。
    • 重叠方法： 使用特定的 N-gram 方法评估测试数据集与训练数据的重叠程度。根据数据集的不同特征，测试污染的水平有所不同。一些重叠（例如 SQuAD 中的背景信息）并未显著影响性能。
    • 重叠结果： 过滤后，”干净” 数据集的性能与总体结果进行了比较。在 DROP 任务中，虽然模型见过 passage（但未见过问题/答案），但性能变化很小。总体来看，GPT-3 对数据污染的影响不大，表明 GPT-3 对污染的敏感性较低。
InstructGPT Training language models to follow instructions with human feedback

强化学习出现在了大模型中得一个环节

摘要 > 让语言模型更大本身并不使它们更好地遵循用户意图。例如，大型语言模型可以生成不真实、有毒或简单地对用户没有帮助的输出。换句话说，这些模型与他们的用户没有对齐。在本文中，我们展示了通过使用人类反馈进行微调，将语言模型与用户意图对齐在广泛的任务上的途径。从 OpenAI API 提交的一组标签编写提示和提示开始，我们收集了所需模型行为的标记器演示数据集，我们用它来使用监督学习微调 GPT-3。然后，我们收集了模型输出排名数据集，我们用它来使用来自人类反馈的强化学习进一步微调这个监督模型。我们将生成的模型称为 InstructGPT。在对我们的提示分布的人工评估中，尽管参数少 100 倍，但 1.3B 参数 InstructGPT 模型的输出更喜欢来自 175B GPT-3 的输出。此外，InstructGPT 模型显示出有毒输出生成的真实性和减少的改进，同时在公共 NLP 数据集上具有最少的性能回归。尽管 InstructGPT 仍然犯了简单的错误，但我们的结果表明，使用人工反馈进行微调是对齐语言模型与人类意图的一个有前途的方向。

我们通过训练语言模型根据用户意图采取行动来对齐语言模型方面取得了进展（Leike 等人，2018 年）。这包括明确的意图，例如以下指令和隐含的意图，例如保持真实，而不是有偏见的、有毒的或其他有害的。使用Askell等人(2021)的语言，我们希望语言模型是有帮助的(它们应该帮助用户解决他们的任务)、诚实(他们不应该制造信息或误导用户)和无伤害(他们不应该对人或环境造成身体、心理或社会伤害)。

1️⃣ 关键发现

  • 对齐 > 规模：1.3B 的 InstructGPT 优于 175B 的 GPT-3。
  • 指令跟随显著增强：即便 GPT-3 使用 few-shot，也无法弥补。
  • 真实性与幻觉显著改善：闭域任务幻觉率减半。
  • 安全性有限提升：毒性降低，但偏见几乎无改善。

2️⃣ 对齐代价（Alignment Tax）

  • RLHF 会损害部分传统 NLP benchmark 性能。
  • 通过 PPO + 预训练分布约束（PPO-ptx） 可缓解。

3️⃣ 泛化能力

  • 能泛化到：
    • 未参与训练的标注员
    • RLHF 之外的任务分布（代码、多语言）
  • 表明模型学习的是 “抽象的指令遵循能力”，而非任务记忆。

4️⃣ 局限性

  • 仍会：
    • 编造事实
    • 忽略约束
    • 无法识别错误前提
  • 公共 benchmark ≠ 实际使用分布。

数据集 > 三类数据集

基于上述提示，我们构建了三种数据集：

  1. SFT 数据集
    • 标注员示范输出
    • 用于监督微调模型
    • 约 13k 条训练提示
  2. RM 数据集
    • 标注员对模型输出的排序 / 偏好
    • 用于训练奖励模型

  3. PPO 数据集
    • 无人类标注
    • 作为 RLHF 输入提示
    • 约 31k 条训练提示（仅来自 API）

SFT > SFT 不是“最终对齐”，而是给 PPO 提供一个 “人类还能接受的初始策略（initial policy）”。

SFT 数据来自 人类示范（demonstrations）：

(x,y∗)(x, y^*)(x,y∗)

  • xxx：prompt / instruction
  • y∗y^*y∗：人类写的“理想回答”

⚠️ 注意：
这里 没有 reward，没有 preference，只有：

“在这个 prompt 下，人类会怎么回答？”

1️⃣ SFT 用的还是 最大似然（MLE）

数学形式非常朴素：

$$
\mathcal{L}_{\text{SFT}}(\theta)

  • \mathbb{E}{(x, y^*) \sim D}
    \left[
    \sum    {t=1}^{T}
    \log p_\theta\left(y^*t \mid x, y^*{<t}\right)
    \right]
    $$
    也可以写成：

$$
\max_{\theta}
\ \mathbb{E}_{(x, y^*) \sim D}
\left[
\log p_\theta\left(y^* \mid x\right)
\right]
$$
直觉解释

“在看到 prompt x 后，把人类写的回答 y* 当作唯一正确答案去模仿。”

2️⃣ 为什么 MLE 在这里是“对齐的”？

关键不是 loss，而是 数据分布。

SFT 的本质是：

把模型从“互联网说话方式”，
拉向“人类助理说话方式”。

MLE 在这里的作用是：

  • 压高 helpful / polite / structured 的表达
  • 压低
    • 胡言乱语
    • 攻击性语言
    • 无关内容

3️⃣ token-level loss 的含义（重要）

注意：loss 是 逐 token 的。

这意味着 SFT 在学：

  • 回答结构（开头怎么说）
  • 语气（谨慎 / 礼貌）
  • 长度偏好
  • 常见 disclaimers

👉 这也是为什么 SFT 会引入 “过度免责声明 / 冗长” 的副作用。

SFT 用的还是 MLE，但 对齐来自数据而不是 loss

SFT 的目标不是泛化，而是 塑形（shaping behavior）

validation loss 不是 alignment 指标

SFT 定义了 PPO 的“可行空间”

SFT 的 bias 会被 RLHF 放大，而不是消除

1️⃣ Policy（语言模型自回归概率）
$$
\pi_\theta(y|x) = \prod_{t=1}^{T} \pi_\theta(y_t | x, y_{<t})
$$

$x$：prompt

$y = (y_1, \dots, y_T)$：生成序列

$\theta$：模型参数

2️⃣ Reward Model（序列级 reward）
$$
r_\phi(x, y) \in \mathbb{R}
$$

RM 给出 scalar reward，训练目标：

$$
\mathcal{L}{RM}(\phi) = - \mathbb{E}{(x, y_w, y_l)} \left[ \log \sigma(r_\phi(x, y_w) - r_\phi(x, y_l)) \right]
$$

$y_w$：人类偏好 winner

$y_l$：loser

3️⃣ Policy Gradient（REINFORCE）
$$
\nabla_\theta J(\theta) = \mathbb{E}_{y \sim \pi_\theta} \big[ (r_\phi(x, y) - b) \nabla_\theta \log \pi_\theta(y|x) \big]
$$

$b$：baseline（例如平均 reward）

Advantage：$\hat{A} = r_\phi(x, y) - b$

自回归展开：

$$
\log \pi_\theta(y|x) = \sum_{t=1}^{T} \log \pi_\theta(y_t | x, y_{<t})
$$

4️⃣ Token-level ratio
$$
r_t(\theta) = \frac{\pi_\theta(y_t | x, y_{<t})}{\pi_{\text{old}}(y_t | x, y_{<t})}
$$

衡量每个 token 的概率变化

$\pi_{\text{old}}$：前一次策略

5️⃣ Clipped PPO Objective
$$
L^{CLIP}(\theta) = \mathbb{E}_t \Big[ \min \Big( r_t(\theta) \hat{A}_t, , \text{clip}(r_t(\theta), 1-\epsilon, 1+\epsilon) \hat{A}_t \Big) \Big]
$$

$\epsilon$：clip 范围（例如 0.1~0.2）

防止概率被一次拉爆或抹掉

6️⃣ KL penalty（保持 SFT 分布）
$$
L^{KL}(\theta) = \beta , \mathbb{E}{y \sim \pi_\theta} \left[ \log \frac{\pi_\theta(y|x)}{\pi{\text{SFT}}(y|x)} \right]
$$

$\beta$：KL 强度系数

控制 LM 不偏离 SFT distribution

7️⃣ Combined PPO-RLHF Objective
$$
\mathcal{L}{PPO}(\theta) = \mathbb{E}{y \sim \pi_\theta} \Big[ L^{CLIP}(\theta) - L^{KL}(\theta) \Big]
$$

最大化 clipped advantage，同时约束 KL

  • reward 是 sequence-level 的 scalar
  • 通过 log 概率分解，gradient 自动分配给每个 token
  • 所以每个 token 的概率都 朝着提升整个 sequence reward 的方向调整

换句话说：每个 token 用同一个 sequence reward，但梯度通过 log-prob 分解传播到每个 token。

GPT-4 Technical Report

模型辅助的安全流水线

与此前的 GPT 模型类似，我们使用 基于人类反馈的强化学习（RLHF） [40,63] 来微调模型行为，使其更符合用户意图。然而，即使在 RLHF 之后，模型在面对不安全输入时仍可能表现脆弱，并且在安全或不安全输入下都可能出现非预期行为。这类问题往往源于 RLHF 奖励模型数据收集阶段对标注者指令的不充分。

在不安全输入下，模型可能仍会生成不当内容（如犯罪建议）；而在安全输入下，模型又可能表现得过度谨慎，拒绝无害请求或给出过度保守的回答。为了在更细粒度层面引导模型行为，我们大量依赖模型自身作为安全工具。

我们的安全方法主要包括两个组成部分：
1）一组额外的、与安全相关的 RLHF 训练提示；
2）基于规则的奖励模型（Rule-Based Reward Models, RBRMs）。

RBRM 是一组 零样本 GPT-4 分类器，在 RLHF 微调过程中为策略模型提供额外奖励信号，目标是引导正确行为，例如拒绝生成有害内容、但不拒绝无害请求。RBRM 的输入包括：提示（可选）、策略模型生成的输出，以及由人工编写的评估规则（rubric，例如多选形式的规则集合）。RBRM 根据规则对输出进行分类。

例如，我们可以提供一个规则，将模型输出划分为：(a) 符合期望风格的拒绝，(b) 不符合期望风格的拒绝（如含糊其辞或冗长），(c) 包含禁止内容，或 (d) 安全的非拒绝回应。对于请求有害内容的安全相关训练提示，我们对 GPT-4 的拒绝行为给予奖励；相反，在一组保证安全且可回答的提示上，我们奖励 GPT-4 不拒绝。该方法与 Glaese 等人 [71] 以及 Perez 等人 [72] 的工作相关。结合其他改进（如优化 RBRM 权重、增加针对薄弱领域的 SFT 数据），我们能够将模型引导得更接近期望行为。

2.7 隐私（Privacy）

GPT-4 从多种来源学习，包括授权数据、人工创建数据以及公开可用的数据 [59,60]，这些数据可能包含公开的个人信息。因此，我们的模型可能掌握关于在互联网上有显著存在的人物的信息，例如名人和公众人物。

GPT-4 还能够综合多种不同类型的信息，并在一个生成结果中执行多步推理。模型可以完成与个人和地理信息相关的多个基础任务，例如确定某个电话号码的地理位置，或者回答某个教育机构的所在地，并且无需浏览互联网即可完成。在一个示例中，模型可以将Rutgers 大学的邮箱地址与新泽西州区号的电话号码联系起来，并高召回地解释其推理路径是通过这一途径实现的。

通过组合这些能力，GPT-4 在结合外部数据的情况下，可能被用于尝试识别个人。

为了降低模型被用于可能侵犯个人隐私权的风险，我们采取了多种措施，包括：

  1. 对模型进行微调，使其拒绝处理此类请求；
  2. 在可行的情况下，从训练数据中移除个人信息；
  3. 创建自动化模型评估机制；
  4. 监控并响应用户尝试生成此类信息的行为；
  5. 在使用条款和政策中限制此类用途。

此外，我们通过扩展上下文长度和改进用于检索的嵌入模型，可能进一步降低隐私风险，因为这使任务性能更多依赖于用户提供给模型的信息。我们将持续进行相关的研究、开发和技术及流程缓解措施的改进。

CodeX Evaluating Large Language Models Trained on Code

实验数据 > 训练数据来自 2020 年 5 月 GitHub 上的 5400 万个公共仓库，包含 179 GB 小于 1MB 的独特 Python 文件。我们过滤掉了：

  • 可能自动生成的文件
  • 平均行长超过 100 或最大行长超过 1000 的文件
  • 字母数字字符比例很低的文件

过滤后，最终训练数据约 159 GB。

训练方法 > Codex 是基于 自然语言提示（prompt） 进行评估的，因此我们假设从 GPT-3 模型系列 微调会有优势，因为 GPT-3 已经有强大的自然语言表示能力。

  • 出乎意料的是，从预训练语言模型开始微调并未显著提升性能，可能是因为微调数据集太大。
  • 但从 GPT 微调可以让模型 更快收敛，因此我们对所有后续实验都采用这一策略。

训练细节：

  • 使用与对应 GPT 模型相同的学习率，175 步线性 warmup + 余弦学习率衰减
  • 总训练 1000 亿 token，使用 Adam 优化器（β1=0.9，β2=0.95，ε=10^-8），权重衰减 0.1
  • 基于 GPT-3 文本 tokenizer 构建代码 lexer，但由于代码中空白和单词分布不同，需要增加 空白长度表示 token，节省约 30% token

评估方法：

  • 每个 HumanEval 问题组成一个 prompt，包括 header、signature、docstring
  • 使用 Codex 生成 token，遇到停止序列（如 \nclass、\ndef、\n# 等）就停止
  • 采样策略：nucleus sampling，top-p=0.95

局限性 > 虽然 Codex 能够为大多数 HumanEval 问题生成正确解，但仍存在诸多限制：

  1. 训练样本效率低：Codex 的训练使用了 GitHub 上数亿行 Python 代码，远超普通开发者在职业生涯中遇到的代码量。即便是完成入门计算机课程的优秀学生，通常能解决的比例也高于 Codex-12B。
  2. 在某些提示下易出错或反直觉行为：Codex 可能生成 语法错误、未定义变量或函数 的代码，并且难以处理 长或高级系统级的 docstring。通过合成问题实验发现，随着 docstring 中操作链长度增加，模型性能呈 指数下降，而人类程序员不会出现这种问题。

这里说他们的训练规模设计受到 Chinchilla scaling law 的启发。

指的是：

  • Jordan Hoffmann 等人提出的 Chinchilla scaling laws
  • 核心思想：模型参数数量和训练数据量应该成比例增长
  • 不能只一味增大模型参数，还要相应增加训练数据

Chinchilla 的核心发现是：

在固定计算预算下，较小模型 + 更多数据，往往比巨大模型 + 少量数据更有效。

所以这句话说明：

他们在设计模型规模和数据规模时，是按照这种“计算最优 scaling 策略”来的，而不是随便堆参数。
